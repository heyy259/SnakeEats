SnakeEats Tool Writing Guide (for LLMs)
Core Concepts
You are writing tool scripts for a text stream + tool registration system. A tool is a standalone executable that the scanner discovers and invokes inside a text stream, and the execution result is written back into the text stream.
Call flow:
LLM generates @{tool_name|{...params...}} embedded in the text stream
  → Scanner picks up the marker
  → Executor invokes the tool script via subprocess.Popen
  → The tool reads JSON from stdin, runs its logic, and prints JSON to stdout
  → Scanner captures stdout and replaces the marker with the result
---
I/O Contract
Input: Read one line of JSON from sys.stdin.
params = json.loads(sys.stdin.read())
Output: Print one line of JSON to sys.stdout (it must be the last line).
print(json.dumps(result, ensure_ascii=False))
Errors: A non-zero exit code means failure. stderr is logged to the console. Error messages should be output as JSON.
---
The Three Execution Modes
1. Normal Mode (synchronous, most common)
Feature	Description
Marker format	@{tool_name|{"arg1": "val1"}}
Execution	stdin → wait → stdout JSON → marker removed + result replaces it
Use cases	Queries, calculations, one-shot operations
# Full example
import json, sys
def main():
    params = json.loads(sys.stdin.read())
    result = {"success": True, "data": process(params)}
    print(json.dumps(result, ensure_ascii=False))
if __name__ == "__main__":
    main()
2. Background Mode (asynchronous + optional interaction)
Feature	Description
Marker format	@{tool_name|{"$mode":"background", "$process_name":"my_proc", "arg":"val"}}
Execution	Launched non-blocking, the process keeps running
stdin	$keep_stdin: "true" → stdin stays open, can receive send_input() later
Output	Real-time streaming output to the stream specified by $console_stream
System fields ($ prefix, stripped automatically before being passed to the tool):
Field	Type	Description
$mode	string	"background" enables background mode
$console_stream	string	Name of the stream that receives real-time output
$keep_stdin	string	"true" keeps stdin open to receive further input
$timeout	number	Timeout in seconds, 0 = unlimited
$process_name	string	Custom process name, auto-generated as toolname_N if not set
$keep_sys_fields	bool	When true, $ fields are also passed into the tool parameters

Interacting with the Text Stream (optional but recommended)
Tools can read and write text streams directly through text_stream_sdk. The following environment variables are injected into the subprocess by the Executor (the tool does not need to set them itself):
  TEXT_STREAM_SYSTEM_ID — text stream system identifier
  TEXT_STREAM_PORT — text stream service port
  TOOL_REGISTRY_PORT — tool registry service port
  SCAN_STREAM_NAME — name of the stream being scanned (injected automatically at scan time; the tool can use it directly to get the stream object)
import os, json, sys
from text_stream_sdk import System
def main():
    params = json.loads(sys.stdin.read())
    # Get the name of the stream being scanned (injected automatically at scan time, no need to pass it as a parameter)
    target_stream = os.environ.get("SCAN_STREAM_NAME", "")
    # ...run the business logic...
    result = {"success": True, "data": ...}
    print(json.dumps(result, ensure_ascii=False))  # stdout goes to the scanner
    # Write to other streams (logs, notifications, etc.)
    try:
        system = System()
        if target_stream:
            stream = system.get(target_stream)  # get the scanned stream directly
        console = system.get("console")
        console.append(f"[tool] done\n")
    except Exception:
        pass  # degrade silently when the SDK is unavailable
Key APIs:
Method	Description
system.get(name)	Get an existing stream
system.create(name, desc)	Create a new stream
stream.read(start?, end?)	Read stream content (no args = read everything)
stream.read_range(start, end)	Read the [start, end) range
stream.read_lines(start_line?, end_line?)	Read by line number
stream.get_length()	Get the stream content length (character count)
stream.write(text)	Overwrite the entire stream content
stream.append(text)	Append to the end of the stream
stream.prepend(text)	Prepend to the beginning of the stream
stream.insert(pos, text)	Insert at the given position
stream.delete_range(start, end)	Delete the given range
stream.replace_range(start, end, text)	Replace the given range with text
stream.replace_lines(start_line, end_line, text)	Replace the given line range with text
stream.search(pattern, context_before=100, context_after=100, regex=False)	Search the stream and return the surrounding context
stream.search_in_range(pattern, start, end, regex=False)	Search within the given range
stream.get_metadata()	Get the stream metadata
stream.update_description(text)	Update the stream description
stream.set_tag(key, value)	Set a tag
stream.remove_tag(key)	Remove a tag
stream.rename(new_name)	Rename the stream

Scan Position Aware Operations (★★★★★ key section)
When the Scanner finds a @{tool_name|...{...}...} marker in the stream:
  1. It automatically injects the environment variable SCAN_STREAM_NAME = name of the stream being scanned
  2. It automatically stores the marker's position range in the stream into InternalStore:
     Key:  _config_{stream_name}
     Value: {"start": marker start position, "end": marker end position}

The tool can get the stream object via SCAN_STREAM_NAME and use the position aware APIs without passing the stream name manually in its parameters.
  stream_name = os.environ.get("SCAN_STREAM_NAME")
  stream = system.get(stream_name)

【Core Concepts】
  start = position of the first character of the @{...} marker in the stream (0-based, inclusive)
  end   = position right after the last character of the @{...} marker (0-based, exclusive)
         ┌────────────────────────────────────────────────────┐
         │ Stream content: ...before...@{my_tool|{...}}...after...  │
         │ Index:   0  ^  start  ^         ^  end         N        │
         │ Region:  |← get_text_before() →|← get_text_after() →   │
         └────────────────────────────────────────────────────┘

APIs for reading the scan position:
Method	Description
stream.get_replace_config()	Returns {"start": int, "end": int} — the marker's position in the stream
stream.get_text_before()	Read all text before the marker (text[0:start])
stream.get_text_after()	Read all text after the marker (text[end:])

APIs for editing at the scan position:
Method	Description
stream.insert_after(text)	Insert text right after the marker's original position (inserted at end, marker preserved)
stream.replace_in_range(text)	Replace the marker itself with text (the start to end range) and fix the config automatically
stream.replace_before(text)	Replace everything before the marker with text (0 to start)
stream.replace_after(text)	Replace everything after the marker with text (end to the end)
stream.set_replace_config(start, end)	Manually set the replacement range (advanced usage)

【Typical scenario 1: reading the context around the marker】
When a tool needs to understand the context it was called in (for example, an LLM tool that needs to read the discussion already present in the prompt context):
  stream_name = os.environ.get("SCAN_STREAM_NAME")
  stream = system.get(stream_name)
  config = stream.get_replace_config()
  context_before = stream.get_text_before()  # text before the marker
  context_after = stream.get_text_after()    # text after the marker
  # or read only N characters around it
  nearby_before = stream.read(start=max(0, config["start"]-500), end=config["start"])

【Typical scenario 2: replacing the marker itself with the result in place】
In normal mode, the stdout JSON is appended to the end of the stream. If you want to replace the marker in place instead (the marker disappears and the result appears at its original position):
  result_text = f"查询结果：{weather_data}"
  stream.replace_in_range(result_text)  # the marker is replaced by the result and the position updates automatically

【Typical scenario 3: appending content near the marker position】
  # insert right after the marker (does not remove the marker)
  stream.insert_after("\n[处理中] analyzing...")
  # replace the marker once processing is done
  stream.replace_in_range("[已完成] " + result)

【Typical scenario 4: a tool generating a chain of subtools (in-place expansion)】
The orchestrator receives a complex task, decomposes it, and inserts the subtask markers directly at the original position:
  tasks = llm_decompose(goal)  # the LLM decomposes the goal into 3 subtasks
  for task in tasks:
      stream.insert_after("\n@{" + task.tool + "|" + json.dumps(task.params) + "}")
  # finally replace its own marker
  stream.replace_in_range("[已分解为 " + str(len(tasks)) + " 个子任务]")

【Notes】
- SCAN_STREAM_NAME is injected automatically by the Scanner before the tool is called; the tool does not need to set it manually
- The InternalStore config is set automatically by the Scanner before the tool is called; the tool does not need to set it manually
- replace_in_range() fixes the config automatically (end = start + len(new_text))
- insert_after() does not modify the config (start/end stay unchanged)
- replace_before() shifts start and end (delta = len(new_text) - old_start)
- If the SDK is unavailable (the text_stream_sdk import fails), all methods degrade silently without affecting the tool's basic functionality
- ⚠️ get_text_before() / get_text_after() depend on the _config_{stream_name} set by the Scanner,
  and only work on the stream that contains the @{...} marker. When a tool reads other streams
  through the stream parameter, use stream.read() (no args = read everything) instead of these two methods

Error Handling Patterns
try:
    params = json.loads(sys.stdin.read())
except (json.JSONDecodeError, EOFError):
    print(json.dumps({"error": "Invalid JSON input"}))
    sys.exit(1)  # non-zero exit code = failure
# validate the parameters
if not params.get("required_key"):
    print(json.dumps({"error": "Missing required parameter: required_key"}))
    sys.exit(1)
try:
    result = do_work(params)
    print(json.dumps({"success": True, "data": result}))
except Exception as e:
    print(json.dumps({"error": str(e)}))
    sys.exit(1)
Rules: exit(0) + last line parseable as JSON = success. exit(≠0) = failure.

Tool Registration Format
# register a tool definition
sdk.register_tool(
    name="my_tool",             # unique identifier, only [a-zA-Z0-9_] allowed
    description="describe the functionality\nInput: {key: type} → Output: {field: type}",
    tool_path="/path/to/my_tool.py",  # can be a .py file or a directory
    execution_path="/path/to/workdir",  # optional, cwd
    tags={"category": "utility"},
)
description must contain → and describe the input parameters and the output structure; this is the only starting point for an LLM to understand a tool.

Tool Path Resolution
- .py file → run with Python
- .js file → run with Node
- .sh file → run with Bash
- directory → look for main.py / __main__.py / run.py
---
Minimal Template
#!/usr/bin/env python3
"""Tool description\nInput: {x: int, y: int} → Output: {sum: int}"""
import json, sys
def main():
    params = json.loads(sys.stdin.read())
    x, y = params["x"], params["y"]
    print(json.dumps({"sum": x + y}))
if __name__ == "__main__":
    main()
That's all it takes: read the stdin JSON, run the logic, print the stdout JSON. The system handles everything else.

Advanced: Scan Position Aware In-place Editing
In normal mode, the stdout JSON result is appended to the end of the stream. But many scenarios require the tool to be aware of its own call position and perform finer operations at the marker's original location. See the "Scan Position Aware Operations" section above.

Quick reference (the three key methods for in-place editing at the marker):
  stream.insert_after(text)     — insert after the marker (marker preserved, waits for the Scanner to remove it)
  stream.replace_in_range(text) — replace the marker itself with the result text (the purest form of "in-place replacement")
  stream.get_text_before/after  — read the context before and after the marker

Workflow example:
  import os
  from text_stream_sdk import System
  system = System()
  stream = system.get(os.environ.get("SCAN_STREAM_NAME", ""))
  
  # read the context before the marker
  context = stream.get_text_before()
  
  # process based on the context...
  result = process(context, params)
  
  # replace the marker with the result; once done, the marker is gone and the result stays in place
  stream.replace_in_range(f"[结果] {result}")
  # at this point the Scanner finds the marker already removed and skips the cleanup step
